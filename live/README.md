# QUARCC v4b live paper fund

This service marks the last v4b `bw_fresh` book to market and serves it to the
website in the shape `PaperFundClient` already expects.

## What is live and what is frozen

- **Frozen:** the strategy book. `live/book.json` holds the 2026-08-24
  formation (326 names, 188% gross, dollar- and beta-neutral). The model's
  input panel ends with the competition release; a new formation is published
  explicitly with `publish_book.py`.
- **Live:** prices. Bar history is Alpaca SIP; the current session is an IEX
  snapshot. The audited NAV through 2026-09-28 is the anchor
  (`live/nav_anchor.csv`); every later point is computed here.
- **Costs:** a 0.48%/yr drag (borrow + trading) is charged daily, matching the
  audit's calibration. Cash earns the August 2026 T-bill rate (3.72%/yr).

The page therefore says "live marks on the 24 Aug 2026 formation", not "a new
formation every two weeks". Publishing a new book is a separate, explicit step.

## Refresh

```bash
set -a; . ./.env; set +a
python live/refresh.py                 # write Public/portfolios + content JSON
python live/refresh.py --dry-run       # print only
python live/refresh.py --no-intraday   # completed closes only
```

`Public/portfolios` is the zero-infrastructure feed: the static site serves it
at `/portfolios`, so `PUBLIC_PAPER_FUND_API_BASE=https://www.quarcc.com` works
without a separate server. The FastAPI service is for intraday refreshes.
Each run also writes `live/latest_holdings.csv` with current weights, prices,
share counts and unrealised P&L — the file to hand to an execution system.

## Fact sheet

`/paper-fund/quarcc-v4b` renders the full fund fact sheet. `live/factsheet.py`
computes the top strip, growth chart, capture, rolling Ulcer, performance and
calendar tables, top holdings, key statistics, market-state buckets and sector
exposure from the daily NAV, SPY total return, `live/tb3ms.csv` and Cboe's VIX
history. `live/names.csv` supplies the company names. The hero chart uses the
daily series, so it matches the old dashboard chart rather than the monthly
PDF sampling.

## API

```bash
pip install -r live/requirements.txt
uvicorn live.api:app --host 0.0.0.0 --port 8787
```

- `GET /portfolios`
- `GET /portfolios/quarcc-v4b`
- `GET /health`
- `POST /refresh` (set `LIVE_ADMIN_TOKEN` to require `X-Admin-Token`)

Set `LIVE_REFRESH_SECONDS=300` to refresh on a timer inside the API process.
The API shells out to `refresh.py`, so it uses the same code path as cron.

## Publishing the next formation

```bash
python live/publish_book.py --csv /path/to/holdings.csv --date 2026-11-02
```

The CSV may be the `vfinal` holdings shape
(`date,permno,ticker,company_name,weight`) or just `ticker,weight`. The current
live NAV becomes the new entry NAV; the old book is archived under
`live/books/`. Tickers are Alpaca symbols (`BRK.B`, not `BRK/B`).

## Website

No environment variable is needed for the static feed: `PaperFundClient`
defaults to `${window.location.origin}/portfolios`, which is the snapshot in
`Public/portfolios`. Set a base only when a separate API should take over:

```bash
PUBLIC_PAPER_FUND_API_BASE=https://your-api.example.com npm run build
```

If the feed is unreachable, the checked-in
`src/content/portfolios/quarcc-v4b.json` is shown. That file is regenerated by
`refresh.py`, so the fallback is the same snapshot as the feed.

## Data note

The stored Massive key on this box is empty and the one candidate in the
session database returns HTTP 401. The service uses the existing Alpaca
market-data entitlement instead: SIP for completed sessions, IEX for the
current session. Swapping in Massive is a provider change in `fetch_bars` and
`fetch_snapshots`; the rest of the pipeline is unchanged.
